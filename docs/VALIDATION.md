# Validation performed

Validated on 4 October 2026 in the available Linux execution environment, with Python 3.12.14, Java 17, PySpark 3.5.6, MLflow 2.22.0, NumPy 1.26.4, PyArrow 19.0.1 and SQLAlchemy 2.0.40. The supplied Dockerfile targets Python 3.11; Docker was unavailable here, so that image still needs to be built and verified on your host.

## Completed checks

- 10,000-customer integration run: generated data, prepared features, fitted model, registered model, reloaded model, and generated exactly 10,000 scores.
- Full-volume historical snapshot: **2,000,000 rows**.
- Full-volume unlabeled scoring snapshot: **2,000,000 rows**.
- Preparation count checks: **2,000,000 rows per snapshot**.
- Split counts: **1,599,809 train; 200,507 validation; 199,684 test**.
- Full model trained, uploaded through an HTTP MLflow tracking server, registered as version 1, and reloaded from that numeric version for inference.
- Batch inference output: **2,000,000 rows**, with **422,836** above the validation-selected threshold of **0.3**.
- Synthetic holdout ROC-AUC: **0.8428**; PR-AUC: **0.5686**; precision: **0.5153**; recall: **0.5997**; F1: **0.5543**.
- Five targeted tests passed: snapshot/feature contract, feature arithmetic including zero transactions, invalid-data/duplicate rejection, deterministic generation, and unsafe run-ID rejection.
- Python compilation passed; Compose YAML and CloudFormation JSON parsed successfully.
- A pip dependency-resolution dry run accepted the pinned requirements in the available environment. This is not a clean Docker-build test.

## Timings observed locally

Spark used `local[4]`, a 4 GiB Java driver and 16 shuffle partitions. Machine-visible RAM was approximately 9.7 GiB. Times include initialization inside each CLI stage, but exclude Docker build, external scheduling overhead, Snowflake execution and AWS transfers. Training/scoring were resumed after restarting the local HTTP test server, so the sum is **stage execution time**, not an uninterrupted wall-clock benchmark. Do not promise the same runtime on Windows, AWS or different data.

| export | 0.00 |

Export time is zero because local mode bypasses Snowflake/S3. No cloud performance claim is made.

## Not executed here

- Docker image build or Docker Compose startup.
- Airflow scheduler runtime / actual DAG execution in a container; the CLI stages were executed separately in the same dependency order.
- CloudFormation deployment or AWS IAM permissions against a real account.
- Snowflake SQL execution, key-pair authentication or S3 unload.
- A real-cloud two-million-row run.
- Business validation using real customer behavior or actual churn outcomes.

The AWS and Snowflake files are prepared for user-side deployment and validation, not a claim that your accounts were changed. Start with 10,000 customers in cloud mode before the full run.

`examples/full_2m_validation/` contains the measured reports and 100-row Parquet samples. Full raw datasets are regenerated by the project instead of embedded in the ZIP.
